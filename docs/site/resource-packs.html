    Resource packs: what works

    Java Edition resource packs load in Rusty Minecraft: put the folder or .zip in resourcepacks/, pick it on the Resource Packs screen (the same screen as vanilla's) or in game, and every loader reloads from it. This page lists everything a 26.3 resource pack can change and whether Rusty Minecraft honours it, with the proof.

    How it works

    packs.rs finds the packs (FolderRepositorySource: folders and zips, plus the built-in Programmer Art and High Contrast, which only the asset index holds: preparation copies them, horizon-prepare packs repairs older resources), reads pack.mcmeta (format range, overlays, filters) and builds one overlay directory that layers the selected packs over the prepared vanilla resources, later packs winning. Files vanilla reads as a resource stack (language files, sounds.json, font definitions, atlas definitions) are merged layer by layer as vanilla merges them. Every loader then reads that one tree; game/packs.rs (reload_packs) reloads all of them in game, as Minecraft.reloadResourcePacks does. Unchanged selections reuse the overlay (reuse-pack-overlays.md).

    Vanilla 26.3's reload listeners (Minecraft.<init>, Gui, Hud): languages, textures, shaders, sounds, atlases, fonts, grass / foliage / dry foliage colour maps, models (block states, block models, item definitions), equipment assets, paletted textures, entity and block entity renderers, particles, the game renderer (post effects), the level renderer, clouds, GPU warn list, regional compliance, splashes and waypoint styles. Every row below comes from one of them.

    The table

    Works: Rusty Minecraft reads it from the pack and draws or plays it like vanilla. Partly: some of it. No: ignored (the vanilla version stays). Proof: a parity harness in tools/ (compares with the pinned 26.3 client), a unit test, or the loader reading the overlay (vanilla's files go through the same loader, and the harness named checks that loader against vanilla).

    Sky: sun, moon phases, stars, end sky, clouds, rain and snow atlases/celestials.json, textures/environment/ works test_environment_render_parity, test_cloud_render_parity, test_weather_render_parity

    Enchantment glint textures/misc/enchanted_glint_* works item_render/gui.rs, entity.wgsl
    Maps: background, decorations textures/map/, atlases/map_decorations.json works loaded from the overlay
    Paintings, mob effect icons atlases/paintings.json, textures/mob_effect/ works loaded from the overlay

    Post effects (spectating a creeper, spider or enderman; glowing outlines) post_effect/, shaders/post/ no Rusty Minecraft's effects are WGSL; a pack's GLSL post chain isn't run

Except the shaders, the missing pieces are missing vanilla features too, and each vanilla parity fix covers the pack case as well.

    Testing a pack

    tools/test_resource_pack_parity.py builds small packs (folder and zip, overlays, a filter, textures, languages, sounds, fonts, atlases), and a Java oracle answers what vanilla's loaders read from them; Rusty Minecraft's loaders must give the same answers. Never commit third-party packs: build test packs in the harness or the test.

    From docs/resource-packs.md. Rusty Minecraft is a fork of Horizon (MIT).
