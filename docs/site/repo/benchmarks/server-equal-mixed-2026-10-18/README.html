    Horizon's server against vanilla 26.3: mixed bots, equal work (2026-10-18)

    This reruns ../server-mixed-2026-10-18/ with the bots' load made the same on both servers. In that run the explore bots flew as fast as each server sent them chunks. Horizon kept up and vanilla didn't, so Horizon sent 2.9 to 5.9 times as many chunks a second, and vanilla's walking bots got a fifth of the chunks Horizon's got. The comparison of tick times wasn't fair.

    Summary

    • The work was equal at 1 and 10 bots. At 25 bots it was equal in chunks sent a second (158.6 against 157.6); vanilla was still catching up on chunks its bots hadn't had yet, see "Equal work" below. Every bot joined, none was dropped, no chunk was sent twice, and no bot ever waited for the chunk it stood in.
    • Tick time (MSPT), same work:
      • 1 bot: 1.8 ms on Horizon against 11.3 on vanilla;
      • 10 bots: 4.7 against 34.3 ms;
      • 25 bots: 11.7 against 50.5 ms. Vanilla dropped just under 20 TPS (19.8) and its worst 5-second P99 was 1388 ms, against Horizon's 130;
      • 50 bots: Horizon ran at 23.8 ms (20 TPS). Vanilla's watchdog stopped its server 30 s after the last bot joined ("A single server tick took 60.01 seconds").
    • Memory: Horizon's RSS was 4.1 to 4.9 times smaller: 0.69 against 3.40 GB with one bot, 0.95 against 3.87 GB with 25, and 1.03 GB with 50. Vanilla's heap is fixed at 4 GB, so its RSS is mostly that heap.
    • CPU (100 % is one of the machine's 4 threads): 30 against 128 % at 10 bots, 58 against 192 % at 25.
    • What changed since the first run: the first run's vanilla held 50 bots at 29.7 ms because its walking bots got 640 to 1100 chunks each. With the explore bots paced, vanilla serves the walking bots in full (5400 to 6100 chunks each, against Horizon's 6100 to 6600), and that is the load it can't carry at 50.

    Equal work

    tools/server_bench.py now prints a work table after the runs. At each bot count it compares every server's chunks sent a second and first-time chunks a second with the busiest server's. Work counts as equal when both are within 10 % (or within a chunk a second when there are few). The report keeps the table as work.

    Bots Chunks/s (Horizon, vanilla) First-time chunks/s (Horizon, vanilla) Equal
    1 9.94, 9.98 0.01, 0.01 yes
    10 61.35, 61.66 1.79, 1.93 yes
    25 158.57, 157.63 5.78, 8.25 no: vanilla sent 2.5 more first-time chunks a second

    Two settings made the load the same:

    • Explore bots paced at 0.8 blocks a second (--explore-speed 0.8), the rate the 2026-10-17 run showed both servers keep up with. Every bot then follows the same path on both servers. The path is deterministic per bot, and a bot only stops while the chunk it stands in hasn't arrived, which never happened here (Waited 0). So both servers had the same chunks to send.
    • A 300-second warm-up before the 300 measured seconds. A first pass with the old 60-second warm-up (aborted after 10 bots) sent the same chunks a second on both (63.1 against 61.4). But vanilla was still delivering the bots' first views during the measurement (12.9 first-time chunks a second against Horizon's 4.1), so its window held more work than Horizon's. With 300 seconds both were in steady state at 1 and 10 bots. At 25, vanilla still sent 2.5 more first-time chunks a second than Horizon: 1.6 % of all it sent, and its walking bots ended the run with 19 % fewer chunks. Read the 25-bot tick times with that in mind: the extra first-time chunks are work vanilla had still to do because it fell behind.

    Method

    tools/server_bench.py ran each configuration on a fresh server:

    • the same server.properties on both: seed 12345, view and simulation distance 10, offline, creative, difficulty easy, sync-chunk-writes=true, white-list off;
    • gamerule respawn_radius 0, and otherwise vanilla's default game rules (the locator bar on for both);
    • the server waits for Done, the bots join one a second, warm up for 300 seconds and are measured for 300, with /tick query every 5 seconds and RSS and CPU every second.

    The bots are horizon-bots --behaviour mixed: 60 % walk, 20 % explore and 20 % idle, each choice deterministic per bot. All are creative and fly 24 blocks above spawn. walk flies to random points within 48 blocks at 5.6 blocks a second, explore flies straight out at 0.8 blocks a second, and idle hovers.

    Machine. The ThinkPad: Intel Core i7-7500U (2 cores, 4 threads), 32 GB, NixOS. The desktop (24 threads) was meant to run it, but it didn't wake (~/fleet/power wake desktop timed out, as it did for the first run). No other session ran on the ThinkPad during the runs (load.txt, a sample a minute). The servers ran under nice -n 19. The bots ran on the Mac mini (M4 Pro, shared with other work at 70 to 90 % CPU) and reached the ThinkPad over the tailnet.

    What ran.

    • Horizon: the server build from #916 (horizon-client --no-default-features, no sound or controllers) at 519ec121, packaged with xtask package-server and installed with install.sh --archive, as Linux owners will get it. horizon-server ran it as horizon-engine. The game files were prepared from the owner's own Minecraft. horizon-bots and server_bench.py came from this PR.
    • Vanilla: the pinned 26.3 server jar (the owner's own copy) on OpenJDK 25.0.4.1, -Xms4g -Xmx4g.

    server_bench.py stopped after vanilla's 50-bot server crashed and before it wrote its report. mixed-equal.json holds the run lines it printed. The vanilla 50 entry and its error come from that server's log, and the work table was computed with server_bench.work. load.txt is the fleet monitor's view of the machines during the runs.

    Reproduce

    curl -fsSL https://raw.githubusercontent.com/horizon-rust/horizon/main/packaging/server/install.sh | sh
horizon-prepare --prepare --server-jar /path/to/server.jar      # your own copy
cargo build --release -p horizon-bots                            # on the machine that runs the bots
# in a checkout whose .local/minecraft holds the pinned vanilla jars (tools/lab.py prepare):
HORIZON_BENCH_BIN=~/.local/share/horizon/current \
  python3 tools/server_bench.py --servers horizon,vanilla --bots 1,10,25,50 --behaviour mixed \
    --explore-speed 0.8 --warmup 300 --nice 19 \
    --bots-via 'ssh <bots machine>' --bots-bin /path/to/horizon-bots --connect <this machine's address> \
    --out mixed-equal.json
